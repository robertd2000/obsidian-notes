## Как устроен LRU Cache

### Основная концепция

**LRU (Least Recently Used) cache** — это алгоритм кэширования, который удаляет **наименее недавно использованные** элементы при заполнении кэша [[11]]. Когда кэш достигает своей максимальной ёмкости, освобождается место путём удаления элемента, к которому дольше всего не обращались [[8]].

---

### Структуры данных для реализации

Для эффективной реализации LRU cache используется **комбинация двух структур данных** [[1]]:

1. **Hash Map (хэш-таблица)** — обеспечивает O(1) время доступа к элементам по ключу [[7]]
2. **Doubly Linked List (двусвязный список)** — поддерживает порядок использования элементов [[5]]

#### Почему именно эти структуры?

- **Hash Map** даёт быстрое получение/вставку по ключу за O(1) [[13]]
- **Двусвязный список** позволяет:
  - Добавлять/удалять элементы за O(1)
  - Поддерживать порядок: от наиболее недавно использованного (голова списка) к наименее использованному (хвост списка) [[10]]
  - Быстро перемещать элементы при обращении к ним [[18]]

---

### Как работают операции

#### **Get (получение)**
```
1. Проверяем наличие ключа в hash map
2. Если найден:
   - Получаем значение
   - Перемещаем узел в начало списка (помечаем как наиболее недавно использованный)
   - Возвращаем значение
3. Если не найден — возвращаем -1 (или nil)
```

#### **Put (вставка/обновление)**
```
1. Если ключ уже существует:
   - Обновляем значение
   - Перемещаем узел в начало списка
2. Если ключ новый:
   - Создаём новый узел
   - Добавляем в начало списка
   - Добавляем в hash map
   - Если превышена ёмкость:
     * Удаляем последний элемент списка (наименее используемый)
     * Удаляем его из hash map
```

---

### Пример работы (из вашего задания)

```
cache = new LRU(capacity=2)

cache.put(A, 1)  
// Cache: {A=1}
// Список: [A] ← голова (MRU)

cache.put(B, 2)  
// Cache: {A=1, B=2}
// Список: [B → A] ← B стал MRU

cache.get(A)     
// Возвращает 1
// Список: [A → B] ← A перемещён в начало

cache.put(C, 3)  
// Cache превысил capacity, удаляем B (наименее используемый)
// Cache: {A=1, C=3}
// Список: [C → A]

cache.get(B)     
// Возвращает -1 (B был удалён)
```

---

### Временная сложность

Все операции выполняются за **O(1)**:
- `get(key)` — O(1) [[12]]
- `put(key, value)` — O(1) [[6]]

Это достигается благодаря:
- Hash map для быстрого поиска
- Двусвязному списку для быстрого перемещения и удаления элементов [[23]]

---

### Применение в Go

В Go можно реализовать LRU cache используя:
- `map[K]V` для hash map
- Структуру с указателями `prev`/`next` для двусвязного списка
- Или использовать готовую реализацию из `container/list` + map [[24]]

---

### Преимущества и недостатки

**Плюсы:**
- Простота реализации
- O(1) время операций
- Хорошая эффективность для типичных workload'ов [[14]]

**Минусы:**
- Может вытеснять полезные данные при потоковой обработке (cache pollution) [[14]]
- Требует дополнительной памяти для хранения списков

Этот алгоритм широко используется в базах данных, веб-серверах, операционных системах и других системах, где важен быстрый доступ к часто используемым данным.
