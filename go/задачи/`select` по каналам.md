## Разбор кода: `select` по каналам

### Исходный код

```go
package main

func main() {
    ch := make(chan int, 1) // буферизированный канал, ёмкость = 1

    for i := 0; i < 10; i++ {
        select {
        case x := <-ch:
            print(x)
        case ch <- i:
        }
    }
}
```

---

### Пошаговый разбор (17 грейд)

Ключевое правило `select`: если **несколько case готовы** одновременно, выбирается **случайный**. Если **ни один не готов** — `select` блокируется. Если **ровно один готов** — выполняется он.

Канал буферизированный (`cap=1`), значит в него можно записать **одно значение без блокировки**, даже если никто не читает.

| Итерация | `i` | Состояние канала | Готовые case | Что происходит |
|----------|-----|------------------|--------------|----------------|
| 0 | 0 | `[]` (пуст) | только `ch <- 0` | Записываем 0. Канал: `[0]` |
| 1 | 1 | `[0]` (полон) | только `<-ch` | Читаем 0, **print(0)**. Канал: `[]` |
| 2 | 2 | `[]` (пуст) | только `ch <- 2` | Записываем 2. Канал: `[2]` |
| 3 | 3 | `[2]` (полон) | только `<-ch` | Читаем 2, **print(2)**. Канал: `[]` |
| 4 | 4 | `[]` | только `ch <- 4` | Записываем 4. Канал: `[4]` |
| 5 | 5 | `[4]` | только `<-ch` | Читаем 4, **print(4)**. Канал: `[]` |
| 6 | 6 | `[]` | только `ch <- 6` | Записываем 6. Канал: `[6]` |
| 7 | 7 | `[6]` | только `<-ch` | Читаем 6, **print(6)**. Канал: `[]` |
| 8 | 8 | `[]` | только `ch <- 8` | Записываем 8. Канал: `[8]` |
| 9 | 9 | `[8]` | только `<-ch` | Читаем 8, **print(8)**. Канал: `[]` |

> **Важно:** на каждой итерации готов **ровно один** case — либо буфер пуст (можно писать), либо буфер полон (можно читать). Случайного выбора не происходит.

**Вывод:** `02468` (функция `print` не добавляет пробелов и переносов строк).

### 18 грейд: что будет, если канал не буферизированный?

```go
ch := make(chan int) // или make(chan int, 0)
```

Небуферизированный канал означает: **отправка и получение блокируются**, пока с другой стороны не появится соответствующая операция. Запись «висит», пока кто-то не начнёт читать, и наоборот.

**Итерация 0 (`i=0`):**
- `case x := <-ch` — канал пуст, читателей нет → **блокируется**
- `case ch <- 0` — буфера нет, читателя нет → **блокируется**

**Оба case заблокированы** → `select` ждёт вечно.

Поскольку в программе **только одна горутина** (`main`) и ей некому помочь, runtime Go детектирует дедлок и паникует:

```
fatal error: all goroutines are asleep - deadlock!
```

#### Почему именно так?

1. **Небуферизированный канал = синхронная точка встречи.** Отправитель и получатель должны встретиться одновременно.
2. В коде **нет второй горутины**, которая бы читала/писала в канал.
3. `select` не может выбрать ни один case → блокировка навсегда.
4. Планировщик Go видит, что все горутины заблокированы → **panic: deadlock**.

#### Как исправить, чтобы работало с небуферизированным каналом?

Нужна вторая горутина-«партнёр»:

```go
ch := make(chan int)

go func() {
    for x := range ch {
        print(x)
    }
}()

for i := 0; i < 10; i++ {
    ch <- i
}
close(ch)
```

Или использовать буфер (как в исходном коде) — тогда запись не требует одновременного читателя.

### Краткое резюме

| Ситуация | Поведение |
|----------|-----------|
| `make(chan int, 1)` | Чередование запись/чтение, вывод `02468` |
| `make(chan int)` | **Deadlock panic** на первой итерации — оба case в `select` блокируются, второй горутины нет |
| `make(chan int, 2+)` | Запишет несколько значений подряд, потом начнёт читать — вывод будет другим (зависит от ёмкости) |
