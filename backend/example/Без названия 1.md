Ниже — **20 именно backend-проектов/приложений**, не фреймворков.  
Сразу честно: **идеальных production open-source проектов**, где одновременно:

- бизнес-домен типа банка/магазина;
- микросервисы;
- Kafka;
- транзакционный outbox;
- DLQ;
- метрики;
- логи;
- хорошие best practices;

в открытом доступе **очень мало**. Поэтому список состоит из максимально близких вариантов:

1. event-driven Java/Spring примеры с Kafka/outbox/saga;
2. бизнес-ориентированные open-source backend’ы;
3. production-системы с брокерами, очередями, метриками и логами;
4. качественные sample-микросервисы для изучения декомпозиции.

> C++ в основной список почти не включаю сознательно: бизнес-микросервисов на C++ с Kafka/outbox/DLQ в open source практически нет. Там в основном RPC-фреймворки, прокси, СУБД, а не классические бизнес-бэкенды.

# 1. FTGO Application

**GitHub:** https://github.com/microservices-patterns/ftgo-application

## Домен
Доставка еды:
- заказы;
- рестораны;
- кухня;
- доставка;
- пользователи.

## Стек
- Java
- Spring Boot
- Kafka
- MySQL
- Eventuate Tram
- Docker

## Архитектура: что смотреть
```text
ftgo-order-service/
ftgo-kitchen-service/
ftgo-restaurant-service/
ftgo-delivery-service/
ftgo-consumer-service/
ftgo-api-gateway/
ftgo-common/
ftgo-eventuate/
```

## Kafka / outbox / DLQ / метрики
- Kafka: ✅
- Transactional outbox: ✅ через Eventuate Tram
- Saga: ✅
- DLQ: ⚠️ явно бедно, нужно дорабатывать
- Метрики/логи: ⚠️ базовые

## Плюсы
- один из лучших примеров event-driven микросервисов;
- есть бизнес-домен;
- Kafka + outbox + saga;
- хорошо показывает границы сервисов;
- подходит для изучения Java/Spring microservices.

## Минусы
- это учебный проект, не production;
- местами устаревшие зависимости;
- observability слабая;
- DLQ/retry паттерны нужно докручивать самому.

# Важное замечание про DLQ и outbox

В open-source примерах **DLQ часто отсутствует явно**, потому что это уже деталь production-эксплуатации. Обычно тебе нужно смотреть:

- есть ли consumer errors;
- есть ли retry policy;
- есть ли error topic / dead letter queue;
- есть ли idempotency key;
- есть ли transactional outbox;
- есть ли compensation/saga;
- есть ли observability вокруг consumer lag и ошибок.

Если DLQ нет, это нормально для sample-проектов. В своём backend ты должен добавить:
- error topic;
- retry topic;
- DLQ;
- correlation id;
- idempotency;
- metrics consumer failures;
- alerts.
