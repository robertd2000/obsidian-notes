## Что такое сисколл (System Call)

### **1. Определение**

**Сисколл (system call)** — это механизм, с помощью которого пользовательская программа запрашивает услугу у ядра операционной системы [[1]]. Это интерфейс между пользовательским пространством (user space) и ядром (kernel space).

**Примеры сисколлов:**
- Чтение/запись файлов (`read`, `write`)
- Создание процессов (`fork`, `exec`)
- Выделение памяти (`mmap`, `brk`)
- Сетевые операции (`socket`, `connect`, `send`, `recv`)
- Управление процессами (`exit`, `wait`)

---

### **2. Что происходит во время вызова сисколла**

Процесс вызова сисколла включает несколько этапов:

#### **Шаг 1: Пользовательский код**
```c
// Пользователь вызывает библиотечную функцию
int fd = open("file.txt", O_RDONLY);
```

#### **Шаг 2: Переход в режим ядра**
- Программа выполняет специальную инструкцию процессора (например, `syscall` на x86-64 или `svc` на ARM)
- Процессор переключается из **user mode** в **kernel mode**
- Сохраняется контекст пользовательского процесса

#### **Шаг 3: Обработка в ядре**
- Ядро проверяет права доступа и параметры
- Выполняет запрошенную операцию (например, открывает файл)
- Работает с аппаратными ресурсами (диски, сеть, память)

#### **Шаг 4: Возврат результата**
- Ядро возвращает результат (успех или ошибку)
- Процессор переключается обратно в user mode
- Программа продолжает выполнение

**Важно:** Сисколлы — это "дорогие" операции из-за переключения контекста между user space и kernel space.

---

### **3. Сисколл `fork`**

**`fork`** — это сисколл для создания нового процесса [[2]].

**Что делает:**
1. Создает **точную копию** текущего процесса (дочерний процесс)
2. Дочерний процесс получает:
   - Копию адресного пространства родителя
   - Копию файловых дескрипторов
   - Копию стека и кучи
3. Возвращает:
   - **В родителе**: PID дочернего процесса
   - **В дочернем процессе**: 0

**Пример:**
```c
pid_t pid = fork();

if (pid == 0) {
    // Код дочернего процесса
    printf("Я ребенок, мой PID: %d\n", getpid());
} else if (pid > 0) {
    // Код родительского процесса
    printf("Я родитель, создал ребенка с PID: %d\n", pid);
} else {
    // Ошибка
    perror("fork failed");
}
```

**Особенности:**
- Используется **copy-on-write** (копирование при записи) — физическое копирование памяти происходит только при изменении данных
- После `fork` обычно вызывается `exec` для замены программы дочернего процесса

### **4. Сисколл `epoll`**

**`epoll`** — это механизм **I/O multiplexing** в Linux для эффективного мониторинга множества файловых дескрипторов [[3]].

**Зачем нужен:**
- Позволяет одному потоку отслеживать множество сокетов/файлов
- Эффективнее `select` и `poll` для большого количества дескрипторов
- Используется в высокопроизводительных серверах (Nginx, Redis, Node.js)

**Три основных операции:**

#### **1. `epoll_create`**
```c
int epoll_fd = epoll_create1(0);
// Создает новый epoll instance
```

#### **2. `epoll_ctl`**
```c
struct epoll_event event;
event.events = EPOLLIN;  // Мониторить чтение
event.data.fd = socket_fd;

epoll_ctl(epoll_fd, EPOLL_CTL_ADD, socket_fd, &event);
// Добавляет файловый дескриптор в список мониторинга
```

#### **3. `epoll_wait`**
```c
struct epoll_event events[10];
int num_events = epoll_wait(epoll_fd, events, 10, timeout);
// Ждет событий, возвращает количество готовых дескрипторов
```

**Преимущества перед `select`/`poll`:**
- **O(1)** время проверки готовности (вместо O(n))
- Не нужно передавать весь список дескрипторов при каждом вызове
- Поддержка **edge-triggered** и **level-triggered** режимов
- Масштабируется на тысячи соединений

**Пример использования в сервере:**
```c
// Создаем epoll
int epoll_fd = epoll_create1(0);

// Добавляем слушающий сокет
epoll_ctl(epoll_fd, EPOLL_CTL_ADD, listen_fd, &event);

while (1) {
    // Ждем события
    int n = epoll_wait(epoll_fd, events, MAX_EVENTS, -1);
    
    for (int i = 0; i < n; i++) {
        if (events[i].data.fd == listen_fd) {
            // Новое соединение
            int client_fd = accept(listen_fd, ...);
            epoll_ctl(epoll_fd, EPOLL_CTL_ADD, client_fd, &event);
        } else {
            // Данные от клиента
            handle_client(events[i].data.fd);
        }
    }
}
```

---

### **Сравнение механизмов I/O multiplexing**

| Механизм | Макс. дескрипторов | Сложность | Производительность |
|----------|-------------------|-----------|-------------------|
| **select** | 1024 (FD_SETSIZE) | O(n) | Низкая для большого n |
| **poll** | Неограничено | O(n) | Средняя |
| **epoll** | Неограничено | O(1) | Высокая |

### **Сисколлы в Go**

В Go сисколлы используются через пакет `syscall` или `golang.org/x/sys/unix`:

```go
import "golang.org/x/sys/unix"

// Пример epoll в Go
epfd, _ := unix.EpollCreate1(0)

event := unix.EpollEvent{
    Events: unix.EPOLLIN,
    Fd:     int32(fd),
}
unix.EpollCtl(epfd, unix.EPOLL_CTL_ADD, fd, &event)

events := make([]unix.EpollEvent, 10)
n, _ := unix.EpollWait(epfd, events, -1)
```

**Важно:** Go рантайм сам использует сисколлы для:
- Управления горутинами
- Сетевых операций
- Работы с файлами
- Синхронизации

---

### **Итог**

1. **Сисколл** — интерфейс между пользовательской программой и ядром ОС
2. **Вызов сисколла** включает переключение из user mode в kernel mode
3. **`fork`** создает копию текущего процесса
4. **`epoll`** — эффективный механизм мониторинга множества файловых дескрипторов в Linux

Сисколлы — фундаментальный механизм взаимодействия программ с операционной системой, обеспечивающий безопасность и абстракцию аппаратных ресурсов.
